# 집중 체크 (웹 버전: GitHub Pages + Firebase)

노트북 서버 버전(`../probe_app`)과 화면, 흐름, 측정은 같습니다. 다른 점은 **고정 주소(https)로 열리고, 기록이 Firebase에 저장되며, 노트북이 필요 없다**는 것입니다. 무료(Firebase Spark 요금제, GitHub Pages)로 됩니다.

- 참가자 페이지: `https://<깃허브아이디>.github.io/<저장소>/?k=<개인 토큰>`
- 연구자 화면: `https://<깃허브아이디>.github.io/<저장소>/admin.html` (구글 로그인, 등록된 이메일만)
- 플레이리스트 캡처는 앱에 올리지 않고 **연구자에게 카톡으로** 받습니다. 앱에는 "보냈어요 / 끝나고 보낼게요"만 기록합니다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 참가자 페이지 |
| `admin.html` | 연구자 화면: 쇼츠 시간 설정, 참가자 만들기, 완료 현황, 개인 링크와 QR, 기록 내려받기 |
| `firebase-config.js` | Firebase 설정값 (콘솔에서 복사해 붙여 넣음, 공개돼도 됨) |
| `firestore.rules` | 보안 규칙 (콘솔에 붙여 넣음, 연구자 이메일 넣기) |

## 처음 한 번: Firebase 설정 (15분 정도, 계정 주인이 직접)

1. https://console.firebase.google.com 에서 **프로젝트 추가**. 이름 예: `focus-check-ksef`. Google 애널리틱스는 꺼도 됩니다. 요금제는 **Spark(무료) 그대로** 둡니다 (결제 등록 필요 없음).
2. 프로젝트 첫 화면에서 **웹 앱 추가** (`</>` 아이콘). 앱 이름 아무거나, "Firebase 호스팅"은 체크하지 않음. 등록하면 나오는 `firebaseConfig = { ... }` 값을 복사해서 `firebase-config.js`의 "여기에_..." 자리에 붙여 넣습니다 (Claude에게 붙여 줘도 됨).
3. 왼쪽 **빌드 > Firestore Database > 데이터베이스 만들기**. 위치는 **asia-northeast3 (서울)**, **프로덕션 모드**로 만들기.
4. Firestore의 **규칙** 탭에 `firestore.rules` 내용을 통째로 붙여 넣고, `"연구자1@gmail.com"` 자리를 실제 연구자 구글 이메일로 바꾼 뒤 **게시**.
5. 왼쪽 **빌드 > Authentication > 시작하기 > 로그인 방법 > Google** 사용 설정, 지원 이메일 고르고 저장. 같은 화면 **설정 > 승인된 도메인 > 도메인 추가**에 `<깃허브아이디>.github.io` 추가.

## GitHub Pages에 올리기

1. GitHub에서 새 저장소 (예: `focus-check`), **Public**.
2. 이 폴더의 `index.html`, `admin.html`, `firebase-config.js` 를 올립니다 (`firestore.rules`와 이 README는 올려도 되고 안 올려도 됨).
3. 저장소 **Settings > Pages > Branch: main, / (root) > Save**. 1~2분 뒤 `https://<깃허브아이디>.github.io/focus-check/` 로 열립니다.
4. 올린 코드에는 참가자 정보가 없습니다. 개인 토큰은 Firestore에만 있습니다.

## 실험 준비 (IRB 승인 뒤)

1. 연구자 화면에 구글 로그인 → **쇼츠 시간** 3분 저장 (예비 실험 뒤 바꿀 수 있음).
2. **참가자 만들기**에 36 → 만들기. 조건 순서 6가지가 번호 순서대로 돌아가며 배정됩니다. 평소 이어폰 사용자에게 P001~P018, 비사용자에게 P019~P036.
3. 표의 개인 링크를 카톡으로 보내거나 QR을 출력합니다.
4. 실험 뒤 **본 실험 기록 내려받기 (JSON)** → OneDrive 밖 폴더에 보관.

## 작동 점검 (IRB 전에도 됨, 연구 자료로 쓰지 않음)

- `https://<주소>/?test=1&c=N,M` : 블록 2개 짧은 점검 (쇼츠 20초, 공부 2분). 기록은 `testRecords`에 따로 쌓이고, 연구자 화면에서 내려받기와 지우기가 됩니다.
- `&debug=1` 을 붙이면 단계 건너뛰기 버튼이 생깁니다.
- `?test=1&c=N,C,M&shot=home` 처럼 `shot=`으로 한 화면만 띄워 캡처할 수 있습니다 (home, warm, ready, session, probe, reason, post, done).
- Firebase 설정 전(`firebase-config.js`가 "여기에..." 그대로)에는 **미리보기 모드**: 화면은 다 돌지만 저장은 하지 않습니다.

## 보안 규칙이 하는 일

- 참가자는 개인 토큰으로 **자기 참가자 문서 하나만** 읽을 수 있고, 끝낸 블록 목록만 늘릴 수 있습니다.
- 블록 기록은 **새로 만들기만** 됩니다. 참가자는 남의 기록은 물론 자기 기록도 읽거나 고칠 수 없습니다. 토큰과 참가 번호가 맞아야 저장됩니다.
- 참가자 목록, 기록 읽기, 지우기는 규칙에 적은 연구자 이메일로 로그인했을 때만 됩니다.

## 인터넷이 끊기면

Firebase가 기록을 폰 안에 쌓아 두었다가 연결되면 자동으로 올립니다 (같은 폰, 같은 브라우저로 다시 열면 이어서 올라감). 끝 화면에 "기록이 모두 저장됐어요"가 뜰 때까지 닫지 않게 안내합니다.

## IRB 문구 (노트북 버전에서 바뀐 점)

- 기록 저장 위치: 구글 Firebase(Firestore, 서울 지역). 연구자 계정만 읽을 수 있음. 이름은 저장하지 않고 참가 번호와 무작위 토큰만 씀.
- 플레이리스트 캡처: 참가자가 연구자에게 카톡으로 보냄. 카톡에는 보낸 사람 이름이 보이므로, 곡 정보를 참가 번호로 옮겨 적은 뒤 대화방의 사진을 지움.
- 보관과 삭제: 내려받은 기록은 OneDrive 밖에 보관, Firebase의 기록은 대회(ISEF 포함)가 끝나면 지움 (기간은 팀이 정해 계획서에 적음).
